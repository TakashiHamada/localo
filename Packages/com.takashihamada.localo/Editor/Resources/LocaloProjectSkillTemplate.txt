# Localo

Treat `Packages/com.takashihamada.localo/` as the installed tool and `Assets/LocaloAssets/` as project-owned translation data. Never edit a cached package under `Library/PackageCache`; make reusable tool changes in the Localo source repository.

## Workflow

1. Read `Packages/com.takashihamada.localo/README.md` and the project `AGENTS.md`, if present.
2. Inspect `Assets/LocaloAssets/Resources/LocalizationSettings.asset`, registered tables, and affected scenes or prefabs before editing.
3. Preserve existing keys, language columns, and table registrations unless the task explicitly changes them.
4. Use Unity's asset and scene APIs for serialized Unity files. Respect unsaved human changes.
5. UIのボタン・タブ・項目名・見出しは英語に統一する。ツールチップ・補足説明・ダイアログ本文・Guideウィンドウの説明文は日本語にする。翻訳データや人間のコメントの言語は変更しない。
6. ツール側の説明文は、入力する情報の役割や操作方法を汎用的に説明する。特定の作品・キャラクター・世界設定・操作機器を前提とする具体例を入れない。利用者が登録した翻訳文・方針・調査結果・用語・コメントは、このルールを理由に書き換えない。

## Data contract

- Keep `LocalizationSettings.asset` at `Assets/LocaloAssets/Resources/LocalizationSettings.asset` unless the runtime loading contract changes too.
- Keep `translationSourceLanguage` first in `enabledLanguages` and visible in both grids. Keep English enabled as the runtime fallback. Column order follows `enabledLanguages`; target visibility follows `visibleLanguages`.
- Register every runtime table in `registeredTables`, and keep keys unique across all registered tables.
- Resolution is requested language, then English. Missing keys return the key; an explicitly blank base translation stays blank.
- Store intentional line breaks as `<br>`.
- 各行の `comment`（コメント欄）は人間が書くメモ。AIは翻訳の参考として読むだけにし、新規作成・追記・変更・削除・自動補完を行わない。空欄もそのまま残す。
- AIが調査した行の文脈は、コメント欄に書かない。行の `aiScene`（場面）と `aiDisplaySpace`（器）に保存する。人間のメモと調査結果を自動で移動・統合しない。

## 翻訳の文脈と用語集

文脈は2段で持つ。シートが大きい文脈、行が細かい文脈を持つ。

- シート：「Translation」タブの `LocalizationTable.textType`（文章の種類）と `translationInstructions`（話者・性格・口調などシートの声を含む自由記述の翻訳方針）。シートは文章の種類と声の単位であり、1つのシートに複数の話者を混ぜない。話者や基本の口調が変わる文章を見つけたら、シートを分けるよう人間に提案する。AIはシートの設定を変更しない。
- 行：`LocalizationRow.aiScene`（場面：どこで、何がきっかけで、誰に向けて表示されるか）と `aiDisplaySpace`（器：表示する部品・幅・行数・フォントサイズ・自動縮小・表示時間）。どちらもAIがキーをもとに調査して書き、人間は確認だけ行う。
- 共通用語集は `LocalizationSettings.glossary` に保存される。GlossaryタブはTableと同じ表形式で、Source Term・各言語の正式表記・Notesを編集する。Source TermはSetupのSource Languageで選んだ言語で書く用語・行の識別名であり、実際の正式表記は各言語の列に保存する。右端の×で行を削除できる。
- 翻訳前にコンテキストJSONの `glossary` 全体を必ず読み、Notesにある意味・使い方を確認し、対象言語の正式表記を優先する。行単位の翻訳でも同じ手順とする。翻訳後は該当する登録用語が守られているか確認する。人間の指示・確定訳と矛盾したら勝手に決めず報告する。
- 翻訳前に `Localo.Editor.LocaloTranslationContext.ExportToString()`、または `ExportRowToString(table, key)` を呼ぶ。文章の種類・方針・用語集・翻訳文・人間のコメント・場面・器が区別されたJSONを読み、翻訳に反映する。場面や器が空・不明なら、下の手順で調査する。
- 場面と器は `LocaloTranslationContext.SetRowContext(table, key, scene, displaySpace)` で保存する。`null` を渡した項目は変更しない。このAPIはコメント欄・翻訳文・シートの設定を変更しない。旧APIの `SetResearch` は使わない。人間はTableの行ごとのCommentの右にある詳細アイコンから場面と器を確認・修正できる。

### 言語別ガイドとシートの口調

- コンテキストJSONはschema version 6。ルートの`sourceLanguage`の言語を原文とし、他の言語へ翻訳する。原文が空欄なら他言語から推測せず報告する。翻訳元の文章を翻訳先として上書きしない。`languageGuidelines.commonPoints`と翻訳先に対応する`languageGuidelines.languages`を翻訳前に読む。`locale`・`region`・`points`・`notes`と出典を参照する。TranslationタブのLanguage Guidelinesも同じ資料を表示する。
- 既定はen-US・ko-KR・zh-CN・zh-TW・de-DE・fr-FR・es-419・pt-BR。人間の地域・口調の指定、用語集、翻訳者の確定訳を優先し、一般的なガイドで上書きしない。
- 翻訳前にシート全体の原文と既存訳を読み、対象言語ごとの口調方針を決める。人間のシート方針、用語集、同じシートの翻訳者の確定訳を優先し、未指定なら話者・相手・場面から敬語・呼称・語尾などを推定する。人間の翻訳方針の欄を推定結果で書き換えない。
- 同じ話者と相手の関係では口調を揃える。例えば韓国語の합니다体・해요体・반말は関係と場面で使い分け、相手によって変わる敬語や、感情・関係の変化に伴う意図的な切替を一律に揃えない。別シートの訳から話者の口調を無条件に流用しない。
- 対象シート全体が未確認なら`ExportToString()`で取得し、口調方針を決める。全体の確認後は行単位のJSONも使える。推定した言語別の口調方針を作業報告に添える。既存訳との矛盾や関係性の不明点は、調べても解決できなければKey・言語・理由を添えて人間に報告する。
- `ExportToString(targetLanguages: new[] { SystemLanguage.Korean })`のように、ガイドだけを有効な対象言語に絞れる。`ExportRowToString`も同じ引数を持つ。原文・用語集・お手本の言語はこの引数で削除されない。引数を省略すると有効な全言語のガイドを含む。日本語は今回の言語別ガイドの対象外。

### 作品プロファイルと機種の公式表記

- SetupのProject Profileは `LocalizationSettings.projectProfile` に、選択肢のIDだけを保存する（対象年齢・ジャンル・トーン・日本語の漢字の範囲）。選択肢と指針文はパッケージ同梱の `Editor/Resources/LocaloProjectProfileOptions.json` にある。AIはこの設定を変更しない。
- コンテキストJSONの `projectProfile` は、選んだ項目の表示名と `guidance`（指針文）を含む。全言語の語彙・口調・文の長さ・表記の大きな指針にする。シートの方針・用語集・人間の指示・翻訳者の確定訳と食い違う場合はそちらを優先する。`japaneseKanjiRange` は日本語の列にだけ適用する。
- 仮の文字（まだ原文が決まっていない文言の仮置き）や新しい文言を書くときも、`projectProfile` の対象年齢・トーン・漢字の範囲と `platformTerms` に従う。書いた仮の文字は仮であることを作業報告に書く。
- SetupのTarget Platformsで選んだ機種は `LocalizationSettings.targetPlatforms` に保存される。コンテキストJSONの `platformTerms` は、その機種のボタン名・機能名の公式表記（有効な言語のみ）。ボタン名などは対象言語の `text` を使い、`avoid` の書き方を使わない。`status` が `reference` の表記は公式ページが無い言語の参考値なので、採用したら報告する。
- `platformTerms` は一般公開の製品ページの表記で、ロットチェックなどの用語規定ではない。Glossaryに同じ語があればGlossaryを優先し、食い違いを報告する。同梱データに無い機種・用語を推測で補わない。
- QAの `platform-terms` は `avoid` の書き方を、`kanji-range` は範囲を超える漢字を探す。漢字を直すときは、かなに開くか範囲内の語に言い換える。読み（音訓）が範囲内かどうかは機械的に調べられないため、自己レビューで確認する。

### 行の文脈（場面と器）の調査手順

人間がキーを指定して調査を依頼したときに使う。

1. `ExportRowToString(table, key)` で、シートの `textType`・`translationInstructions` と、既存の場面・器・人間のコメントを読む。
2. キーの使用箇所を探す。シーンとプレハブでは `LocalizeTextBase` 派生コンポーネントの `localizationKey`、コードでは `GetLocalizedString("KEY")` や `SetKey("KEY")` を検索する。キーが文字列の組み立てで作られている場合も考慮する。
3. 場面を調べる：どの画面・シーンか、表示のきっかけと条件、誰に向けた文か、前後に表示される文章。
4. 器を調べる：表示に使う部品、RectTransformのサイズ、フォントサイズ、Auto Size、折り返し・Overflowの設定、想定される行数、表示時間（自動で消える表示や字幕など）。
5. 確認できた事実と推測を区別し、根拠（アセットのパス、コードの箇所）を添える。確認できないことは不明と書く。使用箇所が複数あれば、それぞれを書く。
6. `SetRowContext` で保存し、調査したキーと要点を作業報告に書く。

## 翻訳の長さと文脈

- 原文の意味・意図・使用場面・話者の性格や口調を保ち、前後の文章、シートの方針、人間のコメント、用語集に沿って訳す。同じ文脈では用語と言い回しを統一し、文脈が違う同じ語を機械的に同じ訳にしない。
- 特にボタン・ラベルなど短いUI文言は、原文とおおむね同じ表示幅・行数に収まる簡潔な訳を目指す。原文にない説明を足して長くしない。
- 文字数は表示幅の目安として扱う。言語やフォントによって幅が変わるため、文字数の完全一致や一律の倍率を必須にしない。人間が指定した表示領域・長さの制約があれば従う。
- 短くするために重要な意味・条件・否定・口調を損なわない。文脈と長さを両立できない場合や、表示領域が不明で収まりに懸念がある場合は、Key・言語・理由・採用訳・短い代案を作業報告に示して人間の確認に回す。コメント欄には書き込まない。
- 自己レビューで意味・文脈・用語・口調に加えて、原文に対して不必要に長くなっていないかを確認する。実画面でのはみ出しや読みやすさの確認は人間に引き継ぐ。

## 翻訳者担当のシートと言語

- TranslationタブのTranslator Lockは、シートごとの `LocalizationTable.translatorLanguages` に保存される。指定された言語の列全体は翻訳者担当。AIは全行・空欄・今後追加する行も変更しない。アセット直接編集による回避も禁止する。人間からロック設定の変更を明示的に依頼された場合以外は、この設定を変更しない。
- コンテキストJSONの各シートの `translatorLanguages` を確認し、対象言語をAIの翻訳対象から外す。原文が変わっていても、ロックされた訳は書き換えず人間に報告する。
- `translatorExamples` は全シートから集めた翻訳者のお手本であり変更対象ではない。行単位のJSONにも含まれる。各例の `translatorLanguages` に該当する入力済みの訳を、同じ言語・近い文脈の用語・言い回し・口調のお手本として優先的に参照する。他の言語の訳は参考例として区別する。シートの方針や話者の違いを考慮し、用語集・人間の指示と矛盾する場合は報告する。
- CSV取り込みは既定で翻訳者担当の列への変更をerrorにし、全体を中止する。AIは `AllowTranslatorCellChanges` をtrueにせず、`-localoAllowTranslatorChanges` を使わない。人間が翻訳者の納品CSVを取り込む場合や、確定訳の修正を明示的に行う場合のための指定である。人間はTableで文章を修正できる。

## CSV review workflow

Use `Localo.Editor.LocaloCsv` (editor-only, no UI) when translations are reviewed outside Unity:

1. Export: `LocaloCsv.ExportToFile(path)`. Keep this file unchanged as the baseline.
2. The reviewer edits a copy. Columns: `Table`, `Key`, enabled languages (display names), `Comment`.
3. Always dry-run first: `LocaloCsv.ImportFromFile(reviewedPath, new LocaloCsvImportOptions { DryRun = true, BaselineCsvPath = path, ImportComments = false })`, then read `report.ToString()`.
4. Limit columns to what the reviewer was asked to change with `Languages`. AIが実行する取り込みでは、dry-run・本番ともに `ImportComments = false` を必ず指定する。batch modeでは `-localoNoComments` を必ず付ける。
5. Check skipped keys, conflicts, and placeholder warnings with the human, then run the same call without `DryRun`.

Reviewers must save as UTF-8 (Google Sheets, or Excel "CSV UTF-8"); Excel can also turn `+{0}`-style cells into formulas, so review the dry-run list. Import overwrites existing keys cell by cell, never deletes rows, skips unknown keys unless `AddMissingKeys = true`, and writes nothing when any error is reported. When the Editor is closed, use `-executeMethod Localo.Editor.LocaloCsvCommandLine.Export|Import` with `-localoCsv <path>`.

## Runtime integration

- Bind Canvas TMP text with `LocalizeTextMeshProUGUI` and 3D TMP text with `LocalizeTextMeshPro`.
- 新しく作る文字表示に legacy Text（`UnityEngine.UI.Text`）と `TextMesh` を使わない。legacy Text には行頭禁則の機能が無く、日本語・中国語を折り返すと「、」「。」が行頭に来る。UGUI は `TextMeshProUGUI`、3D は `TextMeshPro`、UI Toolkit は `Label` を使う。UI Toolkit では、`PanelSettings.textSettings` に Line Breaking Rules を割り当てた Panel Text Settings を渡す（未割り当てだと禁則が効かない）。
- 手で入れた改行（`<br>`）は禁則の対象外。改行の直後が「、」「。」などで始まらないように訳す。
- Do not place `LocaloManager` manually; it bootstraps before the first scene.
- Switch language with `LocaloManager.Instance.SetLanguage(...)` and fetch dynamic text with `GetLocalizedString(...)`.
- Keep platform-specific language adapters in the consuming project. The public package boundary is `LocaloManager.SetSystemLanguageProvider(...)`.
- Never copy proprietary SDK code, vendor binaries, private package sources, credentials, or machine-specific absolute paths into the public Localo package.

## Verification

1. Compile with the Unity workflow documented by the project and confirm zero errors.
2. Verify registered tables, enabled language columns, and unique keys after data edits.
   After changing translations or text UI, run `Localo.Editor.LocaloQa.RunAll()` (the same checks as the QA tab) and fix or report each Warning and Error. Do not rewrite translator-locked columns to fix an issue; report it instead.
3. In Play Mode, switch languages at least twice and confirm bound and dynamic text updates.
4. Confirm Console errors are zero, then stop Play Mode.
5. Hand visual quality and interactive feel checks to a human with specific items to inspect.
