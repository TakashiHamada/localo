# Localo

Treat `Packages/com.takashihamada.localo/` as the installed tool and `Assets/LocaloAssets/` as project-owned translation data. Never edit a cached package under `Library/PackageCache`; make reusable tool changes in the Localo source repository.

このフォルダの `translation-guide.md` は、翻訳のコツ（全言語共通と言語別）をまとめた参照資料。作業の手順・優先順位・禁止事項は、このファイルだけに書く。

## Workflow

1. Read `Packages/com.takashihamada.localo/README.md` and the project `AGENTS.md`, if present.
2. Inspect `Assets/LocaloAssets/Resources/LocalizationSettings.asset`, registered tables, and affected scenes or prefabs before editing.
3. Preserve existing keys, language columns, and table registrations unless the task explicitly changes them.
4. Use Unity's asset and scene APIs for serialized Unity files. Respect unsaved human changes.
5. UIのボタン・タブ・項目名・見出しは英語に統一する。ツールチップ・補足説明・ダイアログ本文・Guideウィンドウの説明文は日本語にする。翻訳データや人間のコメントの言語は変更しない。
6. ツール側の説明文は、入力する情報の役割や操作方法を汎用的に説明する。特定の作品・キャラクター・世界設定・操作機器を前提とする具体例を入れない。利用者が登録した翻訳文・方針・調査結果・用語・コメントは、このルールを理由に書き換えない。

## Data contract

- Keep `LocalizationSettings.asset` at `Assets/LocaloAssets/Resources/LocalizationSettings.asset` unless the runtime loading contract changes too.
- Keep `translationSourceLanguage` first in `enabledLanguages` and visible in both grids. Keep English enabled as the runtime fallback. Column order follows `enabledLanguages`; target visibility follows `visibleLanguages`.
- Register every runtime table in `registeredTables`, and keep keys unique across all registered tables.
- Resolution is requested language, then English. Missing keys return the key; an explicitly blank base translation stays blank.
- Store intentional line breaks as `<br>`.

## 翻訳に使う情報

コンテキストJSON（schema version 9）で読む。JSONはデータだけを含む。

| API（`Localo.Editor.LocaloTranslationContext`） | 内容 |
| --- | --- |
| `ExportToString()` | 全シートの全行と、作品全体の情報。作業の最初に1回読む |
| `ExportGroupToString(group)` | そのグループの行だけ |
| `ExportRowToString(table, key)` | その行だけ。行がグループに属していれば、グループの全行を含める |

行とグループの書き出しでは、`platformTerms` は空になる（全体の書き出しで読む）。`focusKey` が空でなければ、その行だけを訳し、ほかの行は文脈として読むだけにする。

| JSONの項目 | 内容 | 書く人 |
| --- | --- | --- |
| `sourceLanguage` | 翻訳元の言語。この言語の文章を原文とし、他の言語へ訳す。列の位置やEnglish固定で推測しない | 人間 |
| `glossary` | 全シート共通の用語集。`source` は翻訳元の言語で書いた用語の識別名で、正式表記は各言語の `translations`、意味と使い方は `notes` にある | 人間 |
| `projectProfile` | 作品全体の対象年齢・トーン・日本語の漢字の範囲と、その指針文。`japaneseKanjiRange` は日本語の列にだけ当てはめる | 人間 |
| `languageLessons` | Project Lessons。この作品のその言語で確定した書き方 | 人間 |
| `platformTerms` | 選んだ機種のボタン名・機能名の公式表記。`avoid` は使わない書き方。`status` が `reference` の表記は、公式ページが無い言語の参考値 | 同梱データ |
| `tables[].translationInstructions` | シートの翻訳方針。話者・性格・口調など、シートの声 | 人間 |
| `tables[].translatorLanguages` | 翻訳者担当の言語。この列に入っている訳が、翻訳者の確定訳 | 人間 |
| `rows[].translations` | 各言語の文章 | 人間とAI |
| `rows[].humanComment` | 人間のメモ | 人間 |
| `rows[].aiScene` | 場面。どこで、何がきっかけで、誰に向けて表示されるか | AI |
| `rows[].aiDisplaySpace` | 器。表示する部品・幅・行数・フォントサイズ・自動縮小・表示時間 | AI |
| `rows[].aiGroup`・`aiGroupStep`、`groups` | 続けて表示される行のまとまり（1つの会話、1つの画面の問いと答え）と、その中の位置。`groups[].members` が表示される順に並ぶ | AI |

- シートは声の単位で、1つのシートに複数の話者を混ぜない。話者や基本の口調が変わる文章を見つけたら、シートを分けるよう人間に提案する。
- グループ名は登録された全シートで共通で、別のシートの行も同じグループに入る。位置は番号と分岐の英字をハイフンで交互につなぐ。`2-A`／`2-B` は2に対する選択肢、`2-A-1` はAを選んだ後の続き、`3` は合流後を表す。
- AIが書いた項目（場面・器・グループ）は、推測や不明点を含むことがある。

## 優先順位

食い違いを見つけたら、上の段を優先する。同じ段の中の食い違いは勝手に決めず、Key・言語・理由を添えて報告する。

| 段 | 情報 |
| --- | --- |
| 1 | 人間のその場の指示、翻訳者の確定訳、用語集、シートの翻訳方針、人間のコメント |
| 2 | Project Lessons（`languageLessons`） |
| 3 | Project Profile（`projectProfile`） |
| 4 | 機種の公式表記（`platformTerms`） |
| 5 | `translation-guide.md` |

AIの調査結果（場面・器・グループ）は文脈として使い、人間が書いた情報を上書きする根拠にしない。

## 禁止事項

- 人間のコメント（`comment`）を作成・追記・変更・削除しない。空欄も埋めない。調査結果は場面・器・グループに保存し、要確認の事項は作業報告に書く。
- 翻訳者担当の列（`translatorLanguages`）を変更しない。全行・空欄・今後追加する行が対象で、原文が変わっていても書き換えずに報告する。ロックの解除、アセットの直接編集による回避、`AllowTranslatorCellChanges` と `-localoAllowTranslatorChanges` の使用もしない。
- 翻訳元の文章とキーを変更しない。原文が空欄の行は、他の言語から推測せずに報告する。
- シートの翻訳方針・Translator Lock・Project Profile・Target Platforms・Project Lessons を変更しない。変えたほうがよい点は、文面の案を作業報告に示す。
- 同梱データに無い機種・用語を推測で補わない。
- CSVの取り込みで dry-run を省かない。`ImportComments = false`（batch mode では `-localoNoComments`）を必ず指定する。

## 翻訳の手順

1. `ExportToString()` で全体を読む。用語集は全体を読み、`notes` で意味と使い方を確認する。
2. `translation-guide.md` の「全言語共通」と、翻訳先の言語の節を読む。
3. 対象シート全体の原文と既存訳を読み、翻訳先の言語ごとに次の4つを決める。
   1. 口調。敬語・呼称・語尾は、話者・相手・場面から決める。同じ相手との関係では揃え、相手や場面で意図して変わる箇所は保つ。別のシートの訳から話者の口調を流用しない。
   2. 話者と読み手の年齢に合う語彙の範囲。
   3. 作品を通して固定するキーワードと、対象言語で使う語。
   4. 強調の手段（大文字・くり返しなど）と、1ページあたりの上限。
4. 同じ言語の翻訳者の確定訳を、用語・言い回し・口調のお手本にする。近い文脈のものを優先し、話者の違うシートの口調は持ち込まない。
5. 対象の行の場面や器が空なら、下の手順で調査する。
6. 訳す。グループに属する行は `ExportGroupToString(group)` でまとめて取り出し、前後の行の流れと、問いと答えの対応（言い回し・敬語・呼称）を保つ。
7. `translation-guide.md` の「自己レビュー」で見直し、登録された用語が守られているかを確認する。漢字の読み（音訓）が範囲内かどうかは機械的に調べられないので、ここで確認する。
8. 下の「QA」を実行する。
9. 作業報告を書く。

仮の文字（原文が決まっていない文言の仮置き）や新しい文言を書くときも、同じ情報と優先順位に従う。

### 作業報告に書くこと

- 手順3で決めた、言語ごとの方針。
- 要確認の行：Key・言語・理由・採用した訳・短い代案。意味が二通りに取れる、表示領域に収まるか分からない、情報どうしが食い違う、など。
- 文のリズムや器のために省いた語・足した語。
- 仮の文字を書いた行と、参考値（`reference`）の表記を採用した行。
- 名前がだじゃれ・かばん語で用語集に無い場合の、音を写した表記と、しかけを再現した名前の案。
- QAの結果と、直さずに残した指摘。
- 実画面でのはみ出しと読みやすさは確認していないこと。人間に見てほしい箇所。

### 翻訳者の確定訳から学ぶ

翻訳者の確定訳が入ったシートでは、以前の訳との違いを読み、変えられた理由を推定して、同じ言語のほかのシートの訳に生かす。

- 作品全体に当てはまる書き方は、Project Lessons へ追記する文面の案として作業報告に示す。人間が確認して貼り付ける。話者ごとの声はシートの方針、用語の表記は用語集の担当なので、この案に混ぜない。
- 翻訳者が変えた用語・名前の古い表記が、ほかのシート・用語集・シートの翻訳方針に残っていれば、場所を報告する。

## 行の文脈（場面と器）の調査手順

人間がキーを指定して調査を依頼したときと、翻訳する行の場面や器が空のときに使う。

1. `ExportRowToString(table, key)` で、シートの翻訳方針と、既存の場面・器・人間のコメントを読む。
2. キーの使用箇所を探す。シーンとプレハブでは `LocalizeTextBase` 派生コンポーネントの `localizationKey`、コードでは `GetLocalizedString("KEY")` や `SetKey("KEY")` を検索する。キーが文字列の組み立てで作られている場合も考慮する。
3. 場面を調べる：どの画面・シーンか、表示のきっかけと条件、誰に向けた文か、前後に表示される文章。
4. 器を調べる：表示に使う部品、RectTransformのサイズ、フォントサイズ、Auto Size、折り返し・Overflowの設定、想定される行数、表示時間（自動で消える表示や字幕など）。
5. 確認できた事実と推測を区別し、根拠（アセットのパス、コードの箇所）を添える。確認できないことは不明と書く。使用箇所が複数あれば、それぞれを書く。
6. `LocaloTranslationContext.SetRowContext(table, key, scene, displaySpace)` で保存し、調査したキーと要点を作業報告に書く。`null` を渡した項目は変更されない。人間は、Tableの各行のCommentの右にある詳細アイコンから確認・修正する。

## 行のグループ分けの調査手順

人間がシートやプロジェクト全体のグループ分けを依頼したときに使う。

1. `ExportToString()` で全行と既存の `groups` を読む。
2. 続けて表示される文章を探す。会話のデータやコード（キーの配列・リスト、会話を進める処理、タイムライン）、同じプレハブや画面で順に表示されるUI（確認ダイアログの問いとボタン、質問と答え）、選択肢の分岐を調べる。キーの使用箇所は「場面と器」の手順2と同じ方法で探す。
3. グループ名を付ける。内容がわかる短い名前にし、既存のグループ名は理由なく変えない。位置は書式に従って付ける。
   - 1グループは、場面が変わるまでの1つの会話、または1つの画面の問いと答えにとどめる。章全体のような長い流れはグループにせず、場面（`aiScene`）に書く。
   - 1つの行が属せるグループは1つだけ。複数の流れで使い回すキー（共通のボタンや返事など）はグループに入れず、作業報告に挙げる。
4. 確認できたものだけを登録する。根拠のない推測でグループにしない。不確かなものと、根拠（アセットのパス、コードの箇所）は作業報告に書く。
5. `LocaloTranslationContext.SetRowGroups(new[] { new LocaloRowGroupAssignment(key, group, step), ... })` でまとめて保存する。1件でもキーが無い・位置の書式が違うと、何も保存されない。グループ名と位置を両方空にすると、その行をグループから外す。
6. QAの `groups` を実行し、指摘を直すか報告する。

## QA

`Localo.Editor.LocaloQa` は、訳文とアセットから機械的に判定できる問題を探す。人間が画面で実行するものではなく、必要なときに自分で実行する。

```csharp
using Localo.Editor;
using UnityEngine;

string all = LocaloQa.Report();
string mine = LocaloQa.Report(keys: new[] { "KEY_A", "KEY_B" }, languages: new[] { SystemLanguage.Korean });
string project = LocaloQa.Report(checkIds: new[] { "missing-key", "legacy-text-usage", "line-break-settings" });
string checks = LocaloQa.DescribeChecks();
```

- `Report` は、先頭に重大度ごとの件数、続けて1件1行で指摘を返す。`keys` と `languages` は、表の行を指す指摘だけを絞る。アセットや設定を指す指摘は絞らない。
- `DescribeChecks` は、チェックのIdと、何を調べて何が対象外かの説明を返す。初めて使うときに読む。
- Editorを開いていないときは `Unity -batchmode -quit -projectPath <project> -executeMethod Localo.Editor.LocaloQaCommandLine.Run` を使う。引数は `-localoQaChecks a,b`、`-localoQaKeys A,B`、`-localoQaLanguages Japanese,Korean`、`-localoQaOut <path>`（すべて省略可）。Error があると終了コード1になる。

| いつ | 何を実行するか |
| --- | --- |
| 訳文を書いた・直した後 | 変えたキーと言語に絞って `Report` |
| 文字を出す部品・シーン・プレハブ・キーを使うコードを変えた後 | `missing-key`、`legacy-text-usage`、`line-break-settings` |
| フォントや有効な言語を変えた後 | `missing-glyph` |
| グループ分けを保存した後 | `groups` |
| 作業報告の前 | 全部 |

- Error は実行時に壊れるので直す。Warning は直すか、理由を添えて報告する。Info は意図どおりかを判断する。
- 指摘を消すために、翻訳者担当の列と人間のコメントを書き換えない。報告する。
- 漢字の範囲の指摘は、かなに開くか、範囲内の語に言い換えて直す。
- 画面の見た目（はみ出し・読みやすさ）は調べられない。人間に引き継ぐ。

## CSV review workflow

Use `Localo.Editor.LocaloCsv` (editor-only, no UI) when translations are reviewed outside Unity:

1. Export: `LocaloCsv.ExportToFile(path)`. Keep this file unchanged as the baseline.
2. The reviewer edits a copy. Columns: `Table`, `Key`, enabled languages (display names), `Comment`.
3. Always dry-run first: `LocaloCsv.ImportFromFile(reviewedPath, new LocaloCsvImportOptions { DryRun = true, BaselineCsvPath = path, ImportComments = false })`, then read `report.ToString()`.
4. Limit columns to what the reviewer was asked to change with `Languages`.
5. Check skipped keys, conflicts, and placeholder warnings with the human, then run the same call without `DryRun`.

Reviewers must save as UTF-8 (Google Sheets, or Excel "CSV UTF-8"); Excel can also turn `+{0}`-style cells into formulas, so review the dry-run list. Import overwrites existing keys cell by cell, never deletes rows, skips unknown keys unless `AddMissingKeys = true`, and writes nothing when any error is reported. A change to a translator-locked column is an error; a human who imports a translator's delivery sets `AllowTranslatorCellChanges` themselves. When the Editor is closed, use `-executeMethod Localo.Editor.LocaloCsvCommandLine.Export|Import` with `-localoCsv <path>`.

## Runtime integration

- Bind Canvas TMP text with `LocalizeTextMeshProUGUI` and 3D TMP text with `LocalizeTextMeshPro`.
- 新しく作る文字表示に legacy Text（`UnityEngine.UI.Text`）と `TextMesh` を使わない。legacy Text には行頭禁則の機能が無く、日本語・中国語を折り返すと「、」「。」が行頭に来る。UGUI は `TextMeshProUGUI`、3D は `TextMeshPro`、UI Toolkit は `Label` を使う。UI Toolkit では、`PanelSettings.textSettings` に Line Breaking Rules を割り当てた Panel Text Settings を渡す（未割り当てだと禁則が効かない）。
- Do not place `LocaloManager` manually; it bootstraps before the first scene.
- Switch language with `LocaloManager.Instance.SetLanguage(...)` and fetch dynamic text with `GetLocalizedString(...)`.
- Keep platform-specific language adapters in the consuming project. The public package boundary is `LocaloManager.SetSystemLanguageProvider(...)`.
- Never copy proprietary SDK code, vendor binaries, private package sources, credentials, or machine-specific absolute paths into the public Localo package.

## Verification

1. Compile with the Unity workflow documented by the project and confirm zero errors.
2. Verify registered tables, enabled language columns, and unique keys after data edits.
3. Run the QA above for what you changed.
4. In Play Mode, switch languages at least twice and confirm bound and dynamic text updates.
5. Confirm Console errors are zero, then stop Play Mode.
6. Hand visual quality and interactive feel checks to a human with specific items to inspect.
