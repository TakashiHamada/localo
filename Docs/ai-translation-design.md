## レビューでの追加決定：シートと行の文脈の2段構成

この決定は、後の「コメント欄とAIの調査結果」の節にある「シートの性格付けは自由文とし、文章の種類を個別の必須項目にしない」と、行の `aiResearch` 1欄の構成より優先する。本文の行ごとの話者列（§3.3.1）と `characters.md`（§3.7）は採用しない。

文脈の要素はできるだけ少なくし、「声・場面・器」の3つで考える。声はシート、場面と器は行が持つ。

- **シート（大きい文脈）**：`LocalizationTable.textType`（enum `LocaloTextType`）と、自由記述の `translationInstructions`。
  - 文章の種類はTranslationタブで選ぶ。選択肢は、未指定・操作（UI Controls）・システム（System）・説明（Description）・キャラクターのセリフ（Dialogue）・世界の中の言葉（In-World Text）・名前（Names）・ゲームの外（Out-of-Game）。
  - 話者・性格・口調などの「声」は翻訳方針の自由記述に書く。
  - シートは文章の種類と声の単位であり、1つのシートに複数の話者を混ぜない。話者や基本の口調が変わる場合はシートを分ける。GuideウィンドウとTranslationタブにもこの旨を表示する。
- **行（細かい文脈）**：`LocalizationRow.aiScene`（場面）と `aiDisplaySpace`（器）。
  - 場面は、どこで、何がきっかけで、誰に向けて表示されるか。前後の文章も含む。
  - 器は、表示する部品・幅・行数・フォントサイズ・自動縮小・表示時間など。
  - どちらもAIがキーをもとに使用箇所を調査して書き、人間は確認だけ行う。調査手順は配布用Skillに書く。
  - 旧 `aiResearch` は `[FormerlySerializedAs]` により `aiScene` として読み込む。
- 人間のコメント（`comment`）は今までどおり人間だけが書く。
- 行の詳細ウィンドウ（Localo Details）には、Scene と Display Space の2つの入力欄だけを置く。シートの方針・人間のコメント・行単位のJSONコピーボタンは表示しない。どの行かは、ウィンドウのタブ名にキーを出して示す。JSONは Translation タブの Copy All Context as JSON か、`ExportRowToString` で取得する。
- 変数（プレースホルダー）や用語は、文章と用語集からツールやAIが拾えるため、行の項目にしない。
- 保存APIは `LocaloTranslationContext.SetRowContext(table, key, scene, displaySpace)`。`null` を渡した項目は変更しない。`SetResearch` は場面を保存する互換APIとして `[Obsolete]` で残す。
- コンテキストJSONはschema version 3。各シートに `textType`、各行に `aiScene` と `aiDisplaySpace` を出す（`aiResearch` はなくなる）。CSVの列構成は変えない。

## レビューでの追加決定：翻訳の長さと文脈

- 原文の意味・意図・使用場面・話者の性格や口調を保つ。シートの翻訳方針、人間のコメント、用語集、前後の文章を参照し、同じ文脈で用語と言い回しを統一する。文脈が異なる場合は、同じ語でも適切に訳し分ける。
- 特にボタン・ラベルなど短いUI文言では、原文とおおむね同じ表示幅・行数に収まる簡潔な訳を目指す。原文にない説明を足して長くしない。
- 文字数は表示幅の目安であり、完全一致や一律の倍率は必須にしない。言語・フォントによる幅の違いを考慮し、人間が表示領域・長さの制約を指定している場合は従う。
- 短縮のために重要な意味・条件・否定・口調を損なわない。文脈と長さを両立できない場合や、表示領域が不明で収まりに懸念がある場合は、Key・言語・理由・採用訳・短い代案を作業報告に示し、人間の確認に回す。コメント欄には書き込まない。
- この方針はシート固有の指定がない場合も共通ルールとして適用し、コンテキストJSONの `instructions` と配布用Skillテンプレートに含める。自己レビューでも長さと文脈を確認する。実画面での収まりは人間が確認する。

## レビューでの追加決定：翻訳者担当はシートごとの言語列で指定する

この決定は、本文のセル単位の担当区分・操作案（§3.4、§5.3〜§5.4、§6.3、§7、§9）より優先する。セル単位の担当enumは初期実装に追加しない。

- Translationタブで対象シートを選び、Translator Lockで翻訳者担当の言語にチェックする。`LocalizationTable.translatorLanguages` のリストに保存し、指定された言語の列全体をAIの変更から保護する。空欄や今後追加する行も対象。シートの全言語を保護したければ全言語にチェックする。
- Tableは対象セルに `■` を付ける。人間はTableで文章を修正でき、設定のチェックを外して保護を解除できる。AIは設定解除やアセット直接編集による回避をしない。
- CSV取り込みは既定で、保護対象の変更をerrorにして取り込み全体を中止する。変更されていない訳はerrorにしない。翻訳者の納品CSVや確定訳の修正を人間が意図して取り込む場合に限り、`AllowTranslatorCellChanges = true`／`-localoAllowTranslatorChanges` を使える。設定は維持する。AIはこの指定を使わない。
- コンテキストJSONの各シートに `translatorLanguages` を含める。`translatorExamples` には全シートから翻訳者担当の入力済みの訳がある行を、シートの方針・各言語の文章・人間のコメント・AI調査結果とともに収録する。行単位の書き出しでも全シートのお手本を渡す。スキーマはversion 2。
- AIは同じ言語・近い文脈の翻訳者の訳を、用語・言い回し・口調のお手本として優先的に参照する。他の言語の訳は参考例として区別し、話者やシートの違いに注意する。用語集や人間の指示と矛盾したら報告し、確定訳を勝手に修正しない。
- 初期実装は保護設定・表示・CSVの保護・コンテキストとお手本の書き出しまで。自動翻訳や差分検出は未実装。

## レビューでの追加決定：コメント欄とAIの調査結果

以下は設計レビューで決まったルールであり、本文にあるコメント欄の扱いより優先する。

画面の初期実装として、TableとGuideの間に「Translation」タブを追加した。シートの性格付けは `translationInstructions` の自由文とし、文章の種類・話者・性格・口調を個別の必須項目にはしない。話者や基本の口調が変わる場合はシートを分け、一時的な違いは人間のコメントで補足できる。全シート共通の用語集は `LocalizationSettings.glossary` で管理する。この方針を、本文のText Type・話者列・キャラクター設定の専用画面に関する旧案より優先する。

その後、用語集はTranslationタブから独立した「Glossary」タブへ移した。Guideはタブをやめ、ツールバー右端の「?」ボタンで開く別ウィンドウ（Localo Guide）にした。タブは `Setup → Table → Translation → Glossary` の順に並ぶ。

各行の `aiResearch` と、Commentの右にあるメモアイコンも実装した。アイコン列には見出しを表示しない。`LocaloTranslationContext` のEditor APIと画面のJSONコピーボタンで、方針・用語集・コメント・調査結果をまとめて読み出せる。`SetResearch` は調査結果だけを更新する。自動調査や翻訳ジョブの取り込み・差分検出・Validatorの拡張は、この画面の初期実装には含まない。

UIのボタン・タブ・項目名・見出しは英語、ツールチップ・補足説明・ダイアログ本文・Guideウィンドウの説明文は日本語に統一する。翻訳データと人間のコメントには、この表示言語のルールを適用しない。
ツール側の説明は、入力する情報の役割や操作方法を汎用的に記述し、特定の作品・キャラクター・世界設定・操作機器を前提とする具体例は入れない。

- **コメント欄（`comment`）は人間が書くメモ。** AIは翻訳の参考として読むだけにし、新規作成・追記・変更・削除・自動補完をしない。空欄も埋めない。
- AIに文脈を調査させた結果は、コメント欄とは別の自由記述欄に保存する。人間のメモと調査結果を自動で移動・統合しない。既存のコメントはそのまま残す。
- Tableタブの各行のCommentの右にメモアイコンを置き、開くとそのキーの調査結果を確認できる。アイコン列には見出しを表示しない。普段は本文を表に表示しない。
- AI向けの調査手順には、表示場所・表示条件・表示時間・話者・根拠・不明点を、分かる範囲で記述する目安を設ける。確認できた事実と推測を区別し、確認できないことは不明とする。
- 翻訳ジョブには、詳細を開いたかに関係なく、シートの翻訳方針・人間のコメント・AIの調査結果を区別して渡す。AIの調査結果で人間の指示を上書きしない。
- AIが実行するCSV取り込みは、dry-run・本番ともに `ImportComments = false` を必須とする。batch modeでは `-localoNoComments` を指定する。人間が自分でコメントを編集・取り込みできる既存APIは残す。
- AIの翻訳結果を取り込む入口（§5.3）では、コメント欄を更新対象にしない。調査結果を保存するAPIも、コメント欄を書き換えない設計にする。
- 専用欄が利用できるまでは、AIの調査結果は作業報告に出す。コメント欄を代用しない。

## 1. 目的・スコープ・非目標

### 目的

ローカライズ工程全体をAIに任せ、人間は判断が必要なセルだけを見る運用を、既存のLocaloの上に作る。
目指すのは構想§9の形。

> 日本語テキストを追加・変更する → AIが差分を検出する → Unityから文脈を集める → 各言語へ翻訳する → 自己レビューと機械QAを行う → 自動修正する → 人間には要確認の項目だけを提示する

翻訳者とのやり取りもこの流れに組み込む。外部翻訳者に一部の文言を依頼し、そのセルはAIが触らない。翻訳者が決めた訳は、AIのお手本にする。

### 前提（決定済み）

| 項目 | 決定 |
|---|---|
| 原文言語 | 日本語。Englishはランタイムの基準言語・フォールバック先として残すが、翻訳では「訳す先の1言語」として扱う |
| LLMの実行者 | コーディングエージェント（Claude Code等）。手順はSkillで渡す。Unity側は決まった動作をするツールだけを持ち、LLM APIの呼び出しもAPIキーも持たない |
| 文脈の粒度 | Text Typeや既定の話者はシート（テーブル）単位で持つ。行ごとに変わる話者は「話者」列に、それ以外の補足は既存の `comment` に書く。話者の性格や口調は `characters.md` にまとめる |
| 文字数制限 | 厳密な上限は最初は設けない。意味と文脈を保ち、原文とおおむね同じ表示幅・行数を目指す。収まりが不明・両立困難なら要確認とし、機械QAは長さの比率が極端な場合に警告するだけ |
| 翻訳者の保護指定 | **シートごとの言語列単位**。Translationタブで指定する。本文に残るセル単位の3区分は旧案とする |
| 組み込み方 | 別ツールにせず、Localoに足す。Localo導入済みの既存プロジェクトでも、パッケージを更新すれば壊れずに使える |

### 非目標

- UnityからLLMを直接呼ぶこと
- 承認ワークフロー（下書き → レビュー → 承認）の状態管理
- 厳密なTranslation Memoryエンジン
- 文字数・行数の厳密な管理
- `.xlsx` の直接の読み書き。CSV UTF-8 はExcelでもGoogle Sheetsでも開けるので、外部ライブラリは追加しない

## 3. データ設計

### 3.1 互換性の原則

Localo導入済みのプロジェクトが多いので、データの変更はすべて次の原則に従う。

1. **フィールドは足すだけにする。** 既存フィールドの名前の変更・削除・意味の変更はしない。
2. **`LanguageData` は struct。** 既存アセットに無いフィールドは、0（`default`）として読み込まれる。そのため、新しく足すenumは**必ず値0を「未設定」にする**。
3. **ScriptableObjectの新しいフィールドは、既存アセットではC#の初期化子の値になる。** 初期値は、今の挙動を変えない値にする。
4. **ランタイムの挙動は変えない。** `LocaloDatabase.GetText` の「要求された言語 → English」というフォールバックはそのまま。新しいフィールドはEditorのツールだけが使う。

### 3.2 原文言語

`LocalizationSettings` に足す。

```csharp
[Header("-- Translation --")]
[Tooltip("AI・翻訳者が訳すときの原文言語。ランタイムのフォールバック（English）とは独立。")]
public SystemLanguage translationSourceLanguage = LocalizationLanguages.BaseLanguage;
```

- 初期値はEnglishにする。既存プロジェクトでは、今のプレースホルダー比較（Englishと比較）がそのまま続く。
- 日本語原文のプロジェクトは、SetupタブでJapaneseに切り替える。
- 原文言語は `enabledLanguages` に含まれていなければならない。含まれていなければ、Validatorがerrorにする。
- 原文が日本語でEnglishがまだ訳されていない場合、ランタイムのフォールバックは空になる。そのため翻訳ジョブでは、Englishを最優先の翻訳先にする（§6.1）。

### 3.3 シート単位の文脈

`LocalizationTable` に足す。ランタイムでは使わない。

```csharp
[Header("-- Translation Context --")]
[Tooltip("このシートの文章の種類（UI / Dialogue / Tutorial / System など）。")]
public string textType = string.Empty;

[Tooltip("話者が固定のシートなら、その話者（Character Profileの名前と一致させる）。")]
public string defaultSpeaker = string.Empty;

[TextArea(2, 8)]
[Tooltip("画面の説明、トーン、表示領域の目安など。AI・翻訳者向けの自由記述。")]
public string contextNotes = string.Empty;
```

- `textType` は、プロジェクトごとに種類を増やせるようにenumではなく文字列にする。Skillに推奨値を書く。

### 3.3.1 行ごとの話者

`LocalizationRow` に話者のフィールドを足す。ランタイムでは使わない。

```csharp
[Tooltip("この行の話者（characters.md の見出しの名前）。空ならシートの defaultSpeaker。")]
public string speaker = string.Empty;
```

- 実際の話者は、行の `speaker` があればそれ、空ならシートの `defaultSpeaker`、どちらも空なら「話者なし」（地の文・UIなど）になる。
- 名前は `characters.md` の見出し（`## 名前`）と一致させる。Tableタブでは、見出しの一覧からドロップダウンで選べるようにする（§6.3）。
- 自由記述の `comment` に「話者：〇〇」と書く方法はやめる。書式が揺れやすく、ツールで扱えないため。

### 3.4 セルの種類（3種類）

`LanguageData` に、セルの種類と原文の控えを足す。

```csharp
public enum LocaloCellAssignment { Unset = 0, Ai = 1, Translator = 2 }

[Serializable]
public struct LanguageData
{
    public SystemLanguage language;
    [TextArea(1, 4)] public string text;

    // 以下は追加分。既存アセットでは Unset / null として読み込まれる。
    public LocaloCellAssignment assignment;
    public string sourceSnapshot;
}
```

| 種類 | 意味 | AI | 人（Tableタブで手で編集） | 翻訳者CSVの取り込み |
|---|---|---|---|---|
| **未設定** `Unset` | まだ種類を決めていないセル。既存のデータはすべてこれになる | 空なら訳してよい（訳したらAI担当にする）。**訳が入っていれば上書きしない** | ○ | ○ |
| **AI担当** `Ai` | AIが書いてよいセル。人が直してもよい | ○ | ○ | ○ |
| **翻訳者専用** `Translator` | 外部翻訳者が決めるセル | **×（一切書き込まない）** | ○ | ○ |

- 翻訳者専用が止めるのは**AIの経路だけ**。人が手で直すことや、翻訳者のCSVを取り込むことはできる。
  - ツール側では、AIの翻訳結果の取り込み（§5.3）が翻訳者専用セルを拒否する。
  - AIがアセットファイルを直接書き換えることは、技術的には防げない。そのため、Skillの禁止事項で縛る（§7）。
- AI担当のセルを人が直した場合、AIはその訳を勝手に書き換えない。書き換えてよいのは、原文が変わったとき（訳が古いとき）と、人が明示的に頼んだときだけ。
- 「要確認」は状態として保存しない。AIの作業報告（§7）で一覧にして人に渡す。
- 原文言語のセルは、種類も控えも持たない。
- `SetText` などの既存APIのシグネチャは変えない。種類と控えを扱うAPIは別に足す（例：`SetTranslation(row, language, text)`、`SetAssignment(row, language, assignment)`、`ConfirmUpToDate(row, language)`）。

### 3.4.1 原文の控え（古い訳の検出）

`sourceSnapshot` には、**訳を書き込んだときの原文そのもの**を保存する。原文ハッシュを保存する案もあったが、控えのほうを採用した。

| | 原文ハッシュ（不採用） | 原文の控え（採用） |
|---|---|---|
| 変わったかどうかの判定 | できる | できる |
| どう変わったか | 分からない | 「スタート → ゲームを始める」と分かる |
| AIの訳し直し | 一から訳す | 差分を見て、必要なところだけ直せる |
| 翻訳者への再依頼 | 新しい原文だけを渡す | 前の原文と新しい原文を並べて渡せる |
| 人が見たとき | 意味のない文字列 | インスペクタで読める |
| データ量 | 12文字×言語数 | 原文の長さ×言語数。小〜中規模なら問題にならない |

**記録するとき**

- 訳を書き込んだときに、その時点の原文を控えにコピーする。
- 書き込みの経路は問わない（AIの取り込み、CSVの取り込み、Tableタブでの手での編集）。

**判定**

- 控えと今の原文を比べ、違えば「原文が変わって古くなった訳」（以下「古い訳」）とする。
- 比べる前に、改行コード（CRLF / LF）だけはそろえる。それ以外の違い（空白、記号）は、すべて変更として扱う。

**控えが空のセル**

- 既存のデータや、まだ訳していないセルは、控えが空になる。
- 訳が入っていて控えが空のセルは、「古いかどうか不明」として扱う。古い訳としては扱わない。
- 不明のままにしたくないときは、次の「確認済みにする」操作で控えを記録する。

### 3.4.2 確認済みにする操作

原文の誤字を直した、「！」を足した、といった訳に影響しない変更でも、すべての言語が古い訳になる。これを解消するために、**訳は変えずに、控えだけを今の原文で記録し直す**操作を用意する。

- Tableタブで、セル・行・列をまとめて選んで実行できる（§6.3）。
- Editor API（`ConfirmUpToDate`）としても公開する。
  - AIが原文の変更を「訳に影響しない」と判断した場合は、作業報告に挙げて人に提案する。
  - AIはこの操作を勝手に実行しない。
- 既存プロジェクトでは、全セルを選んでこの操作をすれば、控えを一括で記録できる（§4）。
- 翻訳者専用のセルにも、人が実行できる。

#### 種類の変わり方

```text
未設定（空）     ──AIが訳す──────────▶ AI担当
未設定 / AI担当  ──人が翻訳者専用にする──▶ 翻訳者専用（以後AIは書き込めない）
翻訳者専用       ──人が解除する─────────▶ AI担当 または 未設定
未設定（訳あり） ──人がAI担当にする────▶ AI担当（既存の訳をAIに直させてよくなる）
```

- 種類を切り替えても、控えは変えない。控えを記録するのは、訳を書き込んだときと、確認済みにする操作をしたときだけ。そうしないと、古い訳を切り替えただけで「最新」に見えてしまう。

### 3.5 お手本と参考例（Translation Memoryの代わり）

構想§3の方針どおり、別のTMファイルは作らない。テーブルにある訳を、そのまま参照する。

- **お手本**：翻訳者専用セルの訳。言い回し・トーン・用語の手本として、AIが最優先で参照する。
- **参考例**：それ以外の、訳が入っていて古くないセル（AI担当、および訳の入った未設定）。表現を揃えるために参照する。
- 人がAIの訳を直した結果は、AI担当のセルにそのまま残る。そのため、次回からは参考例として使われる。構想§3の「人間が一度修正した失敗を繰り返さない」は、これで満たす。

### 3.6 共通ナレッジ

プロジェクトデータとして `Assets/LocaloAssets/Knowledge/` に置く。パッケージには同梱しない。

| ファイル | 形式 | 読み手 | 用途 |
|---|---|---|---|
| `glossary.csv` | CSV | Validator ＋ AI | 固有名詞や重要語の正式訳 |
| `forbidden_terms.csv` | CSV | Validator ＋ AI | 禁止表現、優先表現、過去の修正ルール |
| `style_guide.md` | Markdown | AI | 作品全体と言語ごとの翻訳方針 |
| `characters.md` | Markdown | AI ＋ ツール（話者名の一覧と、セクションの抜き出し） | キャラクターの性別・背景・性格・口調・人間関係（§3.7） |
| `LocaloTranslationRules.asset` | ScriptableObject | Validator | 機械的に判定できる規則と閾値。インスペクタから調整する |

- 機械的に検査するものはCSVにする。`LocaloCsvFormat` で読め、翻訳者もExcelで編集できる。C#標準にはYAMLパーサーが無いので、YAMLは避ける。
- LLMだけが読むものは、書きやすいMarkdownにする。

`glossary.csv` のヘッダー。言語の列は、`LocaloCsv` と同じ表示名を使う。各プロジェクトの固有名詞や共通用語を登録する。

```csv
Source,English,Japanese,Korean,Note
```

`forbidden_terms.csv` のヘッダー。禁止表現・優先表現・理由は、各プロジェクトで指定する。

```csv
Language,Forbidden,Preferred,Reason
```

`LocaloTranslationRules`（ScriptableObject）の例：

- `allCapsRules`：テーブル名（空なら全テーブル）× 言語。例：`MainTable × English`
- `lengthRatioWarning`：原文との長さ比がこれを超えたら警告。言語ごとに設定できる
- `forbiddenCharacters`：言語ごとの使用禁止文字

### 3.7 キャラクター設定（`characters.md`）

話者の性格や口調は、キーやシートには持たせず、`characters.md` の1か所にまとめる。シートの `defaultSpeaker` と行の `speaker` は、このファイルのどのキャラクターかを指す名前だけを持つ。同じキャラクターは多くの行に出てくるので、設定を変えるときに直すのは1か所で済む。

**書式**

- キャラクターごとに `## 名前` の見出しを立てる。ツールは、この見出しで名前の一覧を作り、セクションを抜き出す。
- 見出しの下の項目は、次の雛形をそろえて使う。分からない項目は空のままでよい。

```markdown
## キャラクター名
- 性別・年齢：
- 立場・背景：
- 性格：
- 一人称／二人称：
- 原文言語の口調：
- 言語ごとの口調：
- 人間関係・呼び方：
- プロジェクト内の参考セリフ：
- 避けること：
```

**訳すうえで特に大事な項目**

- **性別**：フランス語・スペイン語・ポルトガル語では、形容詞などの形が話者の性別で変わる。
- **言語ごとの口調**：日本語の口調を各言語でどう表すかを決めておく。韓国語の반말／존댓말、フランス語の tu／vous は、相手との関係で決まる。
- **人間関係・呼び方**：相手によって口調が変わるキャラクターに必要。
- **台詞の例**：AIが口調をそろえる手本にする。その話者の行にある翻訳者専用セルの確定訳も、お手本として使う。

**ツールでの使い方**

- 翻訳ジョブ（§6.1）には、その行の話者のセクションだけを抜き出して入れる。ファイル全体を読ませるより、キャラクターの取り違えが減る。
- 会話の相手が分かる場合は、相手のセクションも入れる。人間が `comment` に書いた情報、または根拠を確認したAIの調査結果から参照する。AIは `comment` に追記しない。
- Validator（§6.2）で、`defaultSpeaker` と `speaker` の名前が `characters.md` にあるかを確認する。
- 最初は、テキストエディタで `characters.md` を直接編集する。Localoの画面に専用タブを作るのは、必要になってから（§10）。

## 4. 既存プロジェクトの移行

セルの種類を3つにしたので、専用の移行ツールは要らない。

1. **パッケージを更新する。**
   - 全セルが「未設定」として読み込まれる。ランタイムもTableタブも、今までどおり動く。
   - AIは、訳の入った未設定セルを上書きしない。そのため、何もしなくても既存の訳は守られる。
2. **Setupタブで原文言語を設定する**（日本語原文ならJapanese）。
3. **必要なら、セルの種類を切り替える。**
   - 既存の訳もAIに直させたいシートや列は、Tableタブでまとめて選択し、「AI担当」にする。
   - 翻訳者に任せるセルは「翻訳者専用」にする。
   - 何もしなければ、AIは空のセルだけを訳す。
   - 今の訳が今の日本語に合っているなら、全セルを選んで「確認済みにする」（§3.4.2）。これで控えが記録され、以後は古い訳を検出できるようになる。
4. **Knowledgeの雛形を作る。**
   - Setupタブのボタンで、`Assets/LocaloAssets/Knowledge/` に空の雛形を作る（ヘッダー行だけのCSVと、見出しだけのMarkdown）。
   - 既存のファイルは上書きしない。
5. **翻訳Skillを入れる。**
   - 既存の `localo` Skillの更新と、翻訳Skill（§7）の追加を、今のインストーラにある「確認してから置き換える」流れで行う。

## 5. 翻訳者とのやり取り（既存CSVの拡張）

既存の `LocaloCsv` を作り直さず、オプションを足す。

### 5.1 翻訳者向けexportの絞り込み

`LocaloCsvExportOptions`（新規）を受ける `ExportToString` / `ExportToFile` のオーバーロードを足す。

| オプション | 内容 |
|---|---|
| `Tables` | 対象のテーブル |
| `Keys` | 対象のKey |
| `Languages` | 出力する言語の列。原文言語の列は常に出力する |
| `OnlyTranslatorCells` | 翻訳者専用のセルを含む行だけを出す |
| `OnlyStaleOrEmpty` | 空か、原文が変わって古くなったセルを含む行だけを出す |

| `IncludePreviousSource` | 古い訳を含む行に、「訳したときの原文」の列（例：`Japanese (Previous)`）を足す。翻訳者は前後の原文を比べて、必要なところだけ直せる |
| `IncludeSpeaker` | 実際の話者の列（`Speaker`）を足す |

- 基本の列構成は今のまま（`Table`, `Key`, 言語…, `Comment`）にし、翻訳者には種類の列を見せない。
- `(Previous)` と `Speaker` は参考の列とし、importでは読み飛ばす。今は未知の列があるとerrorになるので、この2つだけを例外として認める。
- batch modeのフラグも足す（例：`-localoTables`、`-localoOnlyTranslatorCells`、`-localoOnlyStaleOrEmpty`）。
- 2つを組み合わせて「翻訳者専用、かつ空か古い」で書き出せば、翻訳者への依頼分になる。

### 5.2 翻訳者CSVの取り込み

- 今の `ImportFromFile`（baseline、dry-run、`Languages`、`ImportComments`）をそのまま使う。新しいオプションは足さない。AIが取り込みを実行する場合は、dry-run・本番ともに `ImportComments = false` を必須とする。
- 書き込んだセルには、原文の控えを記録する（§3.4.1。どの経路でも共通）。
- 翻訳者から受け取る手順は、今のREADMEにある「export → baselineを保存 → dry-run → 本番」と同じ。

### 5.3 AIの訳の取り込み

AIの訳も、同じimportの中核を通す。中核とは、`ImportPlan` の作成、検証、`Apply` の部分のこと。入口は、翻訳ジョブの結果JSON（§6.1）にする。

- 書き込んだセルは「AI担当」にし、原文の控えを記録する。
- **翻訳者専用のセルに変更が含まれていたら、errorにして何も書き込まない**（全体を中止するという既存のルールに従う）。
- 訳の入った未設定セルは、skipしてレポートに出す。

### 5.4 セルの種類の切り替え

- Tableタブで、選択したセルを「未設定／AI担当／翻訳者専用」にまとめて切り替えられるようにする。行・列の選択は、既存の複数選択をそのまま使う。
- 同じ操作を Editor API（例：`LocaloCellAssignments.Set(keys, languages, assignment)`）としても公開し、AIからも呼べるようにする。
- 翻訳者に依頼する**前に**翻訳者専用にしておけば、依頼中にAIがそのセルを訳してしまうことを防げる。

## 6. ツール設計

すべてEditorのC#で書き、Editor起動中（uloop等でEditorのC#を実行）とbatch modeの両方から呼べるようにする。結果は人間が読めるテキストと、機械が読めるJSONの両方で返す。

### 6.1 翻訳ジョブの書き出しと取り込み

**対象セル**（翻訳先の言語ごと）：

- 未設定で空のセル
- AI担当で、空か、古い訳のセル
- 人が明示的に指定したKey（「この行を訳し直して」）。ただしAI担当のセルに限る
- 翻訳者専用のセルと、訳の入った未設定セルは対象にしない

**ジョブJSONの例：**

```json
{
  "sourceLanguage": "Japanese",
  "targetLanguages": ["English", "Korean"],
  "knowledge": {
    "styleGuide": "Assets/LocaloAssets/Knowledge/style_guide.md",
    "characters": "Assets/LocaloAssets/Knowledge/characters.md"
  },
  "items": [
    {
      "table": "<テーブル名>",
      "key": "<対象キー>",
      "tableContext": { "textType": "<文章の種類>", "contextNotes": "<シートの文脈>" },
      "speaker": "<話者名>",
      "speakerProfile": "<プロジェクトに登録された話者の設定>",
      "comment": "<人間が書いたメモ>",
      "source": "<現在の原文>",
      "current": {
        "English": { "text": "<現在の訳>", "previousSource": "<訳したときの原文>" },
        "Korean": { "text": "", "previousSource": "" }
      },
      "targets": ["English", "Korean"],
      "neighbors": [
        { "key": "<前後のキー>", "source": "<前後の原文>", "English": "<対応する訳>" }
      ],
      "glossaryHits": [],
      "examples": [
        { "key": "<参考キー>", "source": "<参考の原文>", "English": "<参考の訳>", "kind": "translator" }
      ]
    }
  ]
}
```

- `examples`：同じシートにあるお手本（`kind: translator`）と参考例（`kind: reference`）を数件入れる。お手本を先に並べる。最初は単純に選び、類似度による選び方は §9 P6 で足す。
- `glossaryHits`：原文に含まれる用語集の語を入れる。
- `speaker`：実際の話者（§3.3.1）。`speakerProfile` には、その話者のセクションを `characters.md` から抜き出して入れる（§3.7）。
- `previousSource`：古い訳のセルなら、訳したときの原文（控え）。AIは前後の原文の差分を見て、必要なところだけを直す。

**結果JSON：** AIは、各項目に `translations`（言語 → 訳）と、必要なら `review`（要確認の理由）を付けて返す。これを §5.3 の流れで取り込む。`review` は保存せず、取り込みレポートと作業報告に出す。

### 6.2 Validator

`LocaloCsv` の `PlaceholderPattern` / `PlaceholderSignature` / `AddTextWarnings` を、`LocaloTextValidator`（新規、Editor）に切り出す。CSV import、ジョブの取り込み、単独の実行の三つで共有する。比べる相手は、Englishから原文言語（§3.2）に変える。

| 検査 | 重大度 | 備考 |
|---|---|---|
| プレースホルダー `{0}` の集合が原文と一致するか | error | 今の判定を流用する |
| TMPタグ（`<color>`・`<b>`・`<sprite>` など）の開始と終了の対応、原文との集合の一致 | error | |
| `<br>` の数が原文と一致するか | warning | 改行位置は言語によって変わってよい |
| 空欄（原文はあるのに訳がない） | warning | |
| 生の改行 | warning | 今の判定を流用する |
| 禁止表現（`forbidden_terms.csv`） | error | |
| 用語集の遵守：原文に用語があるとき、訳に正式訳が含まれているか | warning | 活用形や複数形があるので、warningにとどめる |
| ALL CAPS（`LocaloTranslationRules`） | error | |
| 長さ比が閾値を超えている | warning | 閾値は `LocaloTranslationRules` に置く |
| 重複Key、原文言語が無効 | error | |
| 話者名（`defaultSpeaker` / `speaker`）が `characters.md` に無い | warning | 表記ゆれや書き忘れを検出する |

- 出力は `LocaloCsvReport` に合わせ、`Errors` と `Warnings` に、テーブル・Key・言語・検査ID・メッセージを持たせる。

### 6.3 Tableタブ

今のTableタブは、上に「テーブルの選択＋検索欄」、下に `Key | 各言語 | Comment` の表がある。これに次のものを足す。

```text
┌ Localo ──────────────────────────────────────────────────────────────┐
│ [<Table> ▼]  検索[        ][Clear]  絞り込み[すべて ▼]          ← 追加 │
│ ▼ シートの文脈                                                 ← 追加 │
│   Text Type [Dialogue]  既定の話者 [      ]                           │
│   メモ [シート全体の翻訳方針                                ]       │
├──────────┬────────┬──────────────┬──────────────────┬─────────┬──────┤
│ Key      │ 話者   │ Japanese      │ English           │ Korean  │Comment│
├──────────┼────────┼──────────────┼──────────────────┼─────────┼──────┤
│ <KEY_01> │<話者>▼ │ <原文>        │◆ <翻訳文>         │■ <翻訳文>│<メモ> │
│ <KEY_02> │<話者>▼ │ <原文>        │◆ <翻訳文> ⚠       │■ (空)    │       │
└──────────┴────────┴──────────────┴──────────────────┴─────────┴──────┘
  ◆＝AI担当  ■＝翻訳者専用（地を薄いグレー）  印なし＝未設定  ⚠＝古い訳
```

- **シートの文脈**
  - 表の上の折りたたみ欄で編集する。インスペクタでも同じ項目を編集できる。
- **話者列**
  - `Key` の右に置く。
  - `characters.md` の見出しの一覧から、ドロップダウンで選ぶ。
  - 空なら、シートの既定の話者を薄く表示する。
  - 話者を使わないシートでは、列ごと隠せる。既存の言語列の表示切り替え（`visibleLanguages`）と同じ考え方にする。
- **key / comment / 訳**
  - 今と同じく、表のセルで編集する（`i` かダブルクリック）。
- **セルの種類**
  - 印と地の濃淡で見分ける。白黒でも区別できるよう、色には頼らない。
  - セル・行・列を選んで、右クリックメニューかショートカットで「未設定／AI担当／翻訳者専用」を切り替える（§5.4）。
- **古い訳（⚠）**
  - ⚠ の付いたセルにカーソルを置くと、ツールチップに「訳したときの原文 → 今の原文」を表示する。
- **確認済みにする**
  - セル・行・列を選んで、右クリックメニューかショートカットで実行する（§3.4.2）。
- **絞り込み**
  - 「翻訳者専用だけ」「古い訳だけ」で、表示する行を絞り込める。
- 見た目とショートカットのキーは、既存のTableタブの作りに合わせる。

### 6.4 使用箇所の検索（後のフェーズ）

- Key から、それを参照しているScene、Prefab、Scriptの一覧を返す。
  - Scene・PrefabはYAMLの `localizationKey: <KEY>` を探し、ヒエラルキー上のパスも返す。
  - Scriptは `GetLocalizedString("<KEY>")` を探す。
- 「同じScene・Prefabで使われている他のKey」も返し、画面上の前後の文脈にする。

## 7. Skill設計

既存の `localo` Skill（データとツールの保守）とは別に、翻訳Skill `localo-translate` を `.agents/skills/localo-translate` に配る。テンプレートは `Editor/Resources/` に置き、同じインストーラで入れる。

SKILL.md に書くこと：

1. **手順**（構想§5の13工程を、ツールに対応させる）
   - ジョブを書き出す
   - 文脈を確認する（シートの文脈、人間の `comment`、AIの調査結果、前後の行）
   - Glossary、Style Guide、Character Profile を確認する
   - お手本と参考例を確認する
   - 翻訳する
   - 自己レビューする（意味、ニュアンス、キャラクター性、一貫性、原文に対する長さ・表示幅の目安）
   - Validator を実行する
   - 自動で修正する
   - 結果JSONを書く
   - dry-run で取り込む
   - 本番で取り込む
   - 作業報告を出す
2. **参照の優先順位**：お手本（翻訳者専用）> Glossary > 禁止表現 > Style Guide > Character Profile（`speakerProfile`）> 参考例 > 一般常識
   - 古い訳を訳し直すときは、`previousSource` と今の原文の差分を確認し、変わった部分だけを直す。言い回しは、できるだけ前の訳に合わせる。
   - 原文の変更が訳に影響しないと判断したら、訳は書き換えない。作業報告で「確認済みにしてよい候補」として人に挙げる。
3. **不明点の調べ方**：使用箇所 → 前後の文章 → Glossary / Style Guide → お手本と参考例 → Character Profile（構想§7の順）。それでも分からなければ、最善の訳を入れたうえで `review` に理由を書く。
4. **要確認に回す条件**：
   - 用語集に無い固有名詞が出てきた
   - 意味が二通りに取れる
   - キャラクター設定と矛盾する
   - 表示領域に収まりそうにない
   - お手本と方針が食い違う
5. **禁止事項**：
   - 人間専用のコメント欄（`comment`）に書き込まない。調査結果は専用欄に保存し、専用欄が利用できなければ作業報告で返す
   - 翻訳者専用のセルと、訳の入った未設定セルに書き込まない（ツールを通さない直接編集も含む）
   - 人が直したAI担当の訳を、原文が変わっていないのに書き換えない
   - Keyや原文を変えない
   - dry-run を省かない
   - Knowledge のファイルを勝手に書き換えない（追記したい場合は提案にとどめる）
6. **LLM QAの観点**（構想§6）：誤訳、ニュアンス、自然さ、キャラクター性、敬語、文脈との整合、表現と用語の一貫性、原文に対する不必要な長文化
7. **作業報告の形式**：
   - 言語ごとの件数（翻訳した数、要確認の数、Validatorの警告数）
   - 要確認の一覧（Key、言語、理由、入れた訳、ほかの候補）
   - 確認済みにしてよい候補の一覧（Key、言語、原文の変更内容）
   - 人はこの一覧だけを見て、必要ならTableタブで直すか、確認済みにする

## 10. 未決事項

1. Tableタブで人が訳を手で直したとき、そのセルが未設定なら、自動でAI担当にするか。（案：しない。種類は人が明示的に決める）
2. 要確認の一覧を、チャットの作業報告とは別に、ファイル（例：`Localization/translation-report.md`）としても残すか。
3. シート全体を翻訳者専用にする既定値が必要か（例：シナリオのシートはすべて翻訳者に任せる）。必要なら、`LocalizationTable` に `translatorLanguages` を足す。
4. 表示領域の目安を、将来構造化するか（今は `contextNotes` と `comment` に自由記述）。
5. キャラクター設定を、Localoの画面（専用タブ）で編集できるようにするか（今は `characters.md` をテキストエディタで直接編集する）。
6. 会話の相手を、話者と同じように列として持つか（今は `comment` に「相手：〇〇」と書く）。
