# Localo AI翻訳 設計

- 更新日：2026-11-13（第9版）
- 第9版で、同じ内容が何か所にも書かれていた状態を整理した。知識の置き場所を1か所ずつに決め、人間が使わない画面（QAタブ、同梱ガイドの閲覧パネル、Platform Terms の閲覧ウィンドウ）をなくし、効果の薄い要素（Text Type、Genre）を削った。
- この資料は現在の設計だけを書く。第8版までの経緯と旧案の全文は git の履歴にある。
- 使い方は [README](../README.md)、AIの作業手順は配布用Skill（`Packages/com.takashihamada.localo/Editor/Resources/LocaloProjectSkillTemplate.txt`）にある。この資料は、なぜその形にしたかを書く。

## 1. 目的と前提

ローカライズの作業をAIに任せ、人間は判断が必要な箇所だけを見る。翻訳者に依頼した訳は、AIが触らず、AIのお手本にする。

| 項目 | 決定 |
|---|---|
| AIの実行者 | Skillを入れたコーディングエージェント。Unity側は決まった動作をする道具（Editor API）だけを持ち、LLMの呼び出しもAPIキーも持たない |
| 原文の言語 | Setup の Source Language で選ぶ。English は実行時のフォールバックとして残す |
| 組み込み方 | 別ツールにせず、Localo に足す。導入済みのプロジェクトがパッケージを更新しても壊れない |
| 文字数の制限 | 厳密な上限は設けない。原文とおおむね同じ表示幅・行数を目指し、収まりが分からなければ人間の確認に回す |

## 2. 2つの原則

1. **1つの知識は1か所にだけ書く。** 同じ規則を複数の場所に写すと、片方だけが更新されてずれる（第8版では、コンテキストJSONの版の表記が資料ごとに違っていた）。
2. **人間が書く場所は画面に、AIが使うものは道具とSkillにする。** 人間が見ない閲覧用の画面は持たない。AIが使う機能は、結果を文章で返すEditor APIと、Skillの「いつ・何を実行するか」で用意する。

## 3. 知識の置き場所

| 知識・機能 | 置き場所 | 書く人 |
|---|---|---|
| AIの作業手順・優先順位・禁止事項 | Skill の `SKILL.md` | パッケージ |
| 翻訳のコツ（全言語共通・言語別） | Skill の `translation-guide.md` | パッケージ |
| 文字の機械的なQA | `LocaloQa` のAPI。使いどきは `SKILL.md` | パッケージ |
| 機種の公式表記・漢字の学年・プロファイルの選択肢 | 同梱JSON（`Editor/Resources`） | パッケージ |
| 作品全体の方針 | Translation タブの Project（Project Profile・Target Platforms・Project Lessons） | 人間 |
| 用語 | Glossary タブ | 人間 |
| シートの声 | Translation タブの Sheet（Translation Guidelines） | 人間 |
| 行のメモ | Table の Comment | 人間 |
| 行の場面・器・グループ | Localo Details | AI。人間が確認する |

人間向けの説明は、その項目がある画面の HelpBox とツールチップに書く。Guide ウィンドウは流れの要約とショートカットだけを持つ。QAの各チェックの説明は、チェックのクラスの `Description` だけに書く。

## 4. 文脈のモデル

文脈の要素はできるだけ少なくし、「声・場面・器」で考える。

- **声**はシートが持つ。`LocalizationTable.translationInstructions` に、文章の種類・話者・性格・口調を自由記述で書く。シートは声の単位で、1つのシートに複数の話者を混ぜない。
- **場面**と**器**は行が持つ。`LocalizationRow.aiScene` は、どこで、何がきっかけで、誰に向けて表示されるか。`aiDisplaySpace` は、表示する部品・幅・行数・フォントサイズ・表示時間。どちらもAIがキーの使用箇所を調べて書く。
- **グループ**は、続けて表示される行のまとまり（1つの会話、1つの画面の問いと答え）。`aiGroup` と `aiGroupStep` で表す。シートが声の単位なので、会話は複数のシートに分かれる。その順番をAIに渡す手段がグループである。リスト上の並びは表示の順と一致するとは限らず、シートもまたげないため、前後の行をそのまま渡す方式は採らなかった。
- 人間のメモ（`comment`）は人間だけが書く。AIの調査結果と混ぜない。

作品全体には、次の3つがある。

- **Project Profile**：対象年齢・トーン・日本語の漢字の範囲。選択肢のIDだけを保存し、表示名と指針文は同梱JSONに置く。自然言語の入力欄は置かない。
- **Target Platforms**：機種のボタン名・機能名の公式表記。一般公開の製品ページの表記で、開発者向けの用語規定は転載しない。
- **Project Lessons**：言語ごとの自由記述。その作品のその言語で確定した書き方（翻訳者の修正から分かったことなど）。AIは保存せず、追記の案を作業報告に示す。

## 5. 優先順位と禁止事項

優先順位の表と禁止事項のリストは `SKILL.md` に1つずつある。ここには考え方だけを書く。

- 人間が決めたもの（その場の指示、翻訳者の確定訳、用語集、シートの方針、コメント）が最上位。その中で食い違ったら、AIは勝手に決めずに報告する。
- 作品ごとの記述（Project Lessons、Project Profile）は、どの作品にも当てはまる同梱の資料（機種の表記、翻訳ガイド）より優先する。用語集は機種の表記より優先する。
- AIの調査結果は文脈であり、人間が書いた情報を上書きする根拠にしない。
- AIが書き換えないもの：人間のコメント、翻訳者担当の列、翻訳元の文章とキー、人間が書く設定。

翻訳者担当の列は、シートごとの言語列で指定する（Translator Lock、`LocalizationTable.translatorLanguages`）。CSVの取り込みは、この列への変更を error にして全体を中止する。人間が翻訳者の納品物を取り込むときだけ、`AllowTranslatorCellChanges` を使う。アセットの直接編集は技術的に防げないので、Skillの禁止事項で縛る。

## 6. コンテキストJSON（schema version 9）

`LocaloTranslationContext` が書き出す。**データだけ**を含み、読み方は Skill が持つ。

| 書き出し | 含むもの |
|---|---|
| 全体（`ExportToString`） | `sourceLanguage`、`languages`、`projectProfile`、`languageLessons`、`platformTerms`、`glossary`、`groups`、全シートの全行 |
| グループ（`ExportGroupToString`） | そのグループの行と目次、`projectProfile`、`languageLessons`、`glossary` |
| 行（`ExportRowToString`） | その行（グループに属していればグループの全行）と `focusKey`、`projectProfile`、`languageLessons`、`glossary` |

- 翻訳者のお手本は、別の項目にしない。全体の書き出しで、各シートの `translatorLanguages` に入っている言語の列を見る。
- 機種の公式表記は量が多いので、全体の書き出しだけに入れる。AIは作業の最初に全体を1回読む。
- 構造を変えたら `LocaloTranslationContext.SchemaVersion` を上げ、Skill を合わせて更新する。変更の履歴は CHANGELOG に書く。
- 保存の入口は `SetRowContext`（場面・器）と `SetRowGroups`（グループ）。どちらもコメント・翻訳文・シートの設定を変更しない。

## 7. QA

`LocaloQa` は、フォントや画面を使わず、訳文とアセットから機械的に判定できる問題だけを探す。見た目の確認は人間が行う。

- 画面は持たない。AIが `LocaloQa.Report` で実行し、結果を作業報告に含める。Editor を開いていないときは `LocaloQaCommandLine.Run` を使う。
- `Report` は、チェックのIdと、キー・言語で絞れる。AIが自分の変えた範囲だけを確かめられるようにするため。行を指さない指摘（設定が無くて調べられなかった、など）は、絞り込んでも残す。
- チェックは1種類1ファイル（`Editor/LocaloQa*Check.cs`）。`ILocaloQaCheck` を実装して `LocaloQa.Checks` に加えると、`Report` と `DescribeChecks` に出る。
- CSVの取り込みの警告とQAは、`LocaloTextPatterns` の同じ判定を使う。

## 8. 翻訳者とのやり取り（CSV）

`LocaloCsv` で書き出し、翻訳者が表計算ソフトで編集し、dry-run で確かめてから取り込む。baseline を渡すと、書き出した後の変更との競合を検出する。AIが取り込むときは、dry-run を省かず、コメントを取り込まない。規則の一覧は README にある。

## 9. 互換性の原則

1. 既存のフィールドの意味は変えない。新しいフィールドは、既存アセットで今の挙動を変えない初期値にする。
2. enum を足すときは、値0を「未設定」にする。
3. 実行時の挙動は変えない。`LocaloDatabase.GetText` の「要求された言語 → English」はそのまま。翻訳用の項目は Editor の道具だけが使う。
4. 項目を削るのは、どの処理も使っていない場合に限る。第9版で削った `textType` と `genres` は、既存アセットを次に保存したときに値が消える。

## 10. 画面の言葉づかい

- UIのボタン・タブ・項目名・見出しは英語、ツールチップ・補足説明・ダイアログ本文・Guide ウィンドウの説明文は日本語にする。
- ツール側の説明は、入力する情報の役割と操作方法を汎用的に書く。特定の作品・キャラクター・操作機器を前提とする例は入れない。

## 11. 見送った案と、やめたもの

| 案 | 判断 |
|---|---|
| セル単位の担当区分（未設定／AI担当／翻訳者専用） | シートごとの言語列（Translator Lock）にした |
| 原文の控えを保存し、原文が変わった「古い訳」を検出する | 未実装 |
| 行ごとの話者列と、キャラクター設定のファイル | 採らない。シートを声の単位にした |
| Knowledge フォルダ（用語集・禁止表現のCSV、スタイルガイド、規則のアセット） | 採らない。Glossary タブ、Project Lessons、QA が担当する |
| 翻訳ジョブのJSONと、結果のJSONの取り込み | 未実装。AIは Unity のAPIか、CSVの取り込みで書き込む |
| 前後の行（リスト上の隣）を文脈として渡す | グループに置き換えた |
| 使用箇所を検索する専用の道具 | Skill の調査手順と、QAの `missing-key` で代用する |
| 翻訳専用の別のSkill | 採らない。Skillは1つにし、翻訳のコツだけを参照ファイルに分けた |
| JSONに指示文・言語別ガイド・お手本の一覧を入れる | やめた。Skillと全体の書き出しに一本化した（第9版） |
| QAタブ、同梱ガイドの閲覧パネル、Platform Terms の閲覧ウィンドウ | やめた。人間が使わない画面は持たない（第9版） |
| シートの Text Type、Project Profile の Genre | やめた。どの処理も使わず、AIに足す情報も少なかった（第9版） |
| 禁止表現・長さの比率・大文字の規則のQA | 未実装 |
| お手本の類似検索、厳密な翻訳メモリ、承認ワークフロー、`.xlsx` の読み書き、Unity からのLLMの直接呼び出し | 対象外 |
